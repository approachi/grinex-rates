# Сопроводительное письмо

## Выбор технологий

### Go 1.25
Последняя стабильная версия на момент разработки. Для нового проекта нет причин стартовать на старой версии — берём последнюю и получаем улучшения рантайма, GC и стандартной библиотеки бесплатно.

### Транспорт: gRPC + protobuf
Задание требует gRPC. Protobuf даёт строгую типизацию контракта, встроенную сериализацию и возможность кодогенерации клиентов на любом языке. Reflection включён для удобной отладки через `grpcurl`.

### HTTP-клиент биржи: `resty`
Требование задания. Удобный fluent API поверх стандартного `net/http` — таймауты, query params, автоматический JSON-парсинг без бойлерплейта.

### Драйвер БД: `pgx/v5`
Нативный PostgreSQL-драйвер с прямым доступом к PostgreSQL-специфичным возможностям: типизированные ошибки, встроенный пул соединений `pgxpool`, меньше накладных расходов по сравнению с `database/sql`.

### Конфигурация: `viper` + `pflag`
Viper поддерживает YAML, env vars и флаги в одной связке с чётким приоритетом. Pflag добавляет GNU-совместимые флаги командной строки. Итоговый приоритет: флаг > env var > config.yaml.

### Логирование: `zap`
Структурированное логирование с минимальными аллокациями. Уровень логирования настраивается через конфиг.

### Миграции: `goose`
Версионирование схемы БД с возможностью откатов. Запускается отдельным контейнером при старте — схема всегда актуальна перед стартом приложения.

### Observability
- **OpenTelemetry + Jaeger** — трейсинг запросов от gRPC-хендлера через сервисный слой до SQL-запроса в PostgreSQL
- **Prometheus + Grafana** — метрики: количество вызовов GetRates по методу и статусу, latency, последние значения ask/bid

## Ключевые технические решения

### Методы расчёта курса

Реализованы два метода:
- **topN** — значение из конкретной позиции стакана
- **avgNM** — среднее арифметическое значений в диапазоне позиций [N; M]

Расчёт вынесен в отдельный пакет `calculator`.

### Хранение цен в минорных единицах

Биржа возвращает цены строками с десятичной точкой (`"80.85"`). Для хранения в БД и вычислений они переводятся в целые числа — минорные единицы (`8085`). Это исключает проблемы с точностью float при арифметике.

### Graceful shutdown

При получении `SIGINT` / `SIGTERM` gRPC-сервер завершает обработку текущих запросов перед остановкой. Пул соединений с БД закрывается через `defer`.

## Что было бы добавлено в production

### Инфраструктура кода

- **Валидация входных данных**: сейчас `method`, `position_from`, `position_to` не валидируются на уровне proto — можно передать отрицательные значения или несуществующий метод. В production добавить proto enum для метода и валидацию диапазонов через `protovalidate`
- **Линтер в CI**: `.golangci.yml` с расширенным набором линтеров — `staticcheck`, `gocritic`, `exhaustruct`
- **Swagger/OpenAPI**: при добавлении REST gateway — документация через `grpc-gateway` + `protoc-gen-openapiv2`
- **Параллельные тесты**: `t.Parallel()` в юнит-тестах; для интеграционных — транзакционная изоляция (rollback вместо пересоздания схемы)

### Надёжность

- **Retry + Circuit Breaker** для HTTP-запросов к бирже: при временной недоступности API — экспоненциальный backoff; при систематических ошибках — circuit breaker, чтобы не накапливать зависшие запросы
- **Таймаут контекста на уровне gRPC-хендлера**: сейчас таймаут только на HTTP-клиенте биржи; при деградации БД запрос может висеть дольше допустимого
- **Пул соединений PostgreSQL**: сейчас используются дефолтные настройки pgxpool. В production настроить `MaxConns`, `MinConns`, `MaxConnIdleTime` под нагрузку
- **Кеширование**: если биржа допускает кратковременное кеширование — хранить последний результат в Redis с TTL, чтобы не делать HTTP-запрос при каждом вызове GetRates

### Безопасность

- **TLS для gRPC**: сейчас сервер работает в plaintext-режиме (`-plaintext` в grpcurl). В production — mutual TLS или как минимум server-side TLS
- **Secrets management**: пароль БД через Vault или переменные окружения из секретного хранилища CI/CD, не в config.yaml
- **Сканирование уязвимостей**: `govulncheck` для зависимостей Go, `trivy` для Docker-образа в CI/CD на каждый PR

### Observability

- **Метрики HTTP-клиента биржи**: latency запросов к Grinex API, счётчики ошибок — сейчас эти данные не экспортируются
- **Метрики пула БД**: активные соединения, время ожидания соединения из пула
- **Алертинг**: Alertmanager с алертами по error rate и latency SLO

## Инфраструктура для production

**Kubernetes:**
- 2–5 реплик за Load Balancer, автоскейлинг через `HorizontalPodAutoscaler`
- Сервис stateless — горизонтальное масштабирование без изменений кода
- Конфигурация через `ConfigMap` / `Secret`
- Liveness probe на `HealthCheck`, readiness probe на успешное подключение к БД

**База данных:**
- PgBouncer для connection pooling при большом числе реплик
- Managed PostgreSQL с Multi-AZ — автоматический failover при сбое
- Индекс на `created_at` в таблице `rates` при росте объёма данных; партиционирование по дате для архивирования

**CI/CD:**
- `make test` на каждый PR, сборка образа и деплой в Kubernetes через Helm при мёрдже в main
- Canary-деплой: новый релиз получает часть трафика для постепенного раскатывания
